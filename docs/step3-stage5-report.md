## Changes and code paths

| Confirmed problem | Correction and components |
| --- | --- |
| Core holdout evaluation used observed holdout classes to slice, pad/truncate and renormalize model probabilities. A holdout missing a class therefore discarded genuine probability mass and changed log loss; confusion matrices could omit predictions for absent classes. | `eval/prediction.py` provides shared fitted-class, probability, feature and ordinary-prediction contracts. `eval/holdout.py` retains the model's complete canonical class order, validates labels/probabilities, and evaluates the full distribution. A metric-only copy is reordered to sklearn's sorted-label convention for log loss and multiclass AUROC. Public probabilities retain fitted order and values. Log loss remains computable for a single observed holdout class; undefined full-task AUROC is NaN. |
| Summary/report labels and probability widths could diverge when a class was absent. Macro scores could use inconsistent class sets. | Core confusion matrices, per-class reports and macro-F1 use all fitted classes; zero-support classes receive zero under the existing zero-division convention. `pipeline/steps/train_eval_step.py` aligns plotting payloads to the common training class order and exports the complete class list to PDF data. `plotting/plotter.py` respects explicit label order, rejects incompatible probability widths rather than padding/truncating them, and uses that fixed class set for summary macro metrics. `reporting/final_summary_report.py` uses the same macro-F1 class set; `reporting/per_model_report.py` and holdout CSV extraction omit sklearn's aggregate `micro avg` row from per-class tables. |
| Some probability helpers fabricated probabilities from margins/hard predictions, or used probability argmax in place of estimator decisions. | `predict_estimator` preserves ordinary `model.predict`. Unsupported estimators without probabilities retain hard-prediction metrics but get no fabricated probability loss/AUROC; core ROC/PR inputs do not substitute one-hot hard predictions. `foundation/runner.py` preserves the existing SVM decision path and standalone evaluation definitions, while validating and aligning complete fitted probability schemas. `survival/predict.py` uses ordinary decisions as its main results and assigns the exported confidence to the predicted class, rather than to an unrelated argmax class. |
| Threshold appendices and survival derivatives were included only when holdout F1 improved. | Core training now learns/persists `train_artifacts/thresholds.json` from training OOF before holdout evaluation. Threshold derivatives are always reported/applied when valid learned thresholds exist, independent of holdout improvement. Ordinary predictions remain primary. `pipeline/steps/train_eval_step.py`, `pipeline/steps/survival_step.py` and the final-summary subtitle remove the holdout gate. Historical report-embedded thresholds remain readable without consulting their holdout scores. |
| Threshold class ordering was inferred implicitly, invalid/partial OOF rows could be discarded, and external threshold code silently defaulted missing values. | `train/cv_engine.py` and `train/stacking_engine.py` attach explicit canonical classes to new `CVResult` objects. `eval/thresholds.py` uses that schema, validates complete finite OOF probabilities, reports the ordinary OOF-prediction baseline, and resolves thresholds by fitted class identity. Historical CV results without the new optional field keep their original sorted-training-class convention. Invalid/missing threshold classes or values fail explicitly. Existing numeric-key flat mappings remain readable. The original probability-ratio rule, 19-value default grid and three coordinate passes are preserved. |
| Bare-estimator/external feature matching silently zero-filled missing required features or missing values. | The shared `match_features` orders known fitted features without mutating input or filling missing columns. Fitted partition preprocessors and new stacks retain ownership of their transformations and required-feature checks. | Core raw-count prediction reread mutable gene-length sources and could change its TPM denominator when genes were added/omitted. | `data/processor.py` retains the existing counts → RPK → TPM → log1p algorithm and records its effective gene lengths. `pipeline/steps/raw_count_norm_step.py` saves `preprocessing/raw_count_gene_lengths.joblib` at training and replays the saved gene universe/order and lengths at prediction, ignoring unrelated extra genes and rejecting missing normalization genes. New scoped metadata marks this required state; a missing snapshot is rejected instead of rebuilt. No checkpoint or shared gene-length file is modified. |
| Transductive limma prediction could choose a different pre-correction log transform from the new cohort's scale heuristic. | `pipeline/steps/batch_step.py` records the actual input-log1p decision. The explicitly transductive limma correction itself still runs on the supplied cohort; it is not replaced with an inductive algorithm. Older runs without the decision retain their historical replay path. |
| Legacy CPTAC prediction could refit imputation/offset/filtering on external samples when no saved preprocessing state existed. | `pipeline/steps/cptac_preprocess_step.py` rejects that ambiguous legacy pipeline invocation rather than fitting external data. ## Scientific and configuration scope

Standalone foundation LR, SVM, article/token heads and BERT heads retain their existing fitting and evaluation protocols. Their existing macro-F1 definition is unchanged, as are fixed heads without outer CV and BERT's training-only early stopping. ## Numerical behavior

Primary estimator decisions and complete probability matrices are preserved for valid inputs. Core scores can change when a holdout lacks classes, when a saved class order differs from sorted order, or when old code substituted missing features. Core macro-F1 now averages over all fitted classes, including zero-support classes; weighted F1 still weights by observed support. Invalid schemas now fail rather than produce fabricated metrics. Undefined full-task AUROC remains explicitly missing.

A targeted comparison against actual Stage 4 holdout code from `cabd4eb` used fixed fitted probabilities `[0.45, 0.35, 0.20]` and ordinary class-0 decisions:

| Holdout support | Previous log loss | Corrected log loss | Previous core macro-F1 | Corrected core macro-F1 |
| --- | --- | --- | --- | --- |
| All three classes, equal support | 1.1525892444 | 1.1525892444 | 0.1666666667 | 0.1666666667 |
| Classes 0 and 1 only, equal support | 0.7010213590 | 0.9241649104 | 0.3333333333 | 0.2222222222 |
| Class 0 only | undefined | 0.7985076962 | 1.0 | 0.3333333333 |

Previously the missing-class case renormalized `[0.45, 0.35]` after discarding class 2; the new result retains its 0.20 mass. Ordinary predictions were identical in every comparison. Log: `.step3-validation/stage5/numerical-comparison.log`; data: `numerical-comparison.json`. These are synthetic correctness checks, not manuscript experiments or claims of improved classification.

Threshold values are determined solely by the unchanged training OOF optimization procedure. A targeted core-API test keeps identical training data while changing holdout labels: learned thresholds stay `[0.5, 0.5]`, and the appendix remains present whether the derivative is better or worse. The ordinary result stays primary. Optimized training-OOF F1 is a descriptive fitting score for the threshold search, not an independent estimate of its performance.

Counts normalization is numerically unchanged for a complete fixed input universe and the same lengths. External results can change when previous code used altered length files or a different normalization universe; the new behavior replays saved state. Fitted log, CPTAC median/log2, frozen reference and representation transformations are replayed without fitting. Additional samples do not determine new imputation or representation parameters.

## Compatibility findings

- Model class/import paths and serialized estimator state layouts are unchanged. New `CVResult` metadata has a default for historical instances, and old sorted-class OOF results remain usable. New scoped metadata is additive; original fields and version remain readable.
- New optional training artifacts are `train_artifacts/thresholds.json` and, for core raw-count training, `preprocessing/raw_count_gene_lengths.joblib`. The latter is required when new metadata declares frozen normalization. Old runs without these artifacts keep their historical threshold-report lookup and normalization-source conventions.
- New and historical numeric-key threshold mappings are read by class identity. Invalid or incomplete maps no longer receive silent default thresholds. Their selection/application is independent of saved holdout improvement.
- Bare named estimators, fitted preprocessing wrappers, calibrated models and stacks retain valid complete-input prediction. Missing required inputs now produce errors at the public boundary. The historical stack class itself is unchanged in Stage 5, including its legacy direct prediction path; public evaluation/external matching prevents invalid zero-filled inputs from reaching it.
- Saved-model checks verify bitwise-equal ordinary predictions/probabilities after reload, reordered inputs and repeated inference, with fitting methods replaced by failing spies. Saved model files and the original foundation training bundle remain byte-for-byte unchanged during prediction tests.
- Historical CPTAC runs without fitted preprocessing cannot safely infer raw external preprocessing. The pipeline now rejects these instead of estimating parameters from prediction samples. Historical artifacts lacking feature names can only have their positional width checked; original order/scale must be supplied. Historical raw-count runs without a frozen universe/length snapshot still rely on their original normalization source and input conventions.
- Compatibility across arbitrary dependency versions is not asserted. No existing saved manuscript model or result was accessed or migrated.
