## BulkRNABert audit and preprocessing boundaries

The audit inspected the framework's `prepare_tpm`, `continuous_input`, correction adapters, worker packet/export code and the primary upstream [preprocessing source](https://github.com/instadeepai/multiomics-open-research/blob/main/multiomics_open_research/common/preprocess.py), [tokenizer source](https://github.com/instadeepai/multiomics-open-research/blob/main/multiomics_open_research/common/tokenizer.py), [pretrained factory](https://github.com/instadeepai/multiomics-open-research/blob/main/multiomics_open_research/bulk_rna_bert/pretrained.py) and [checkpoint configuration](https://github.com/instadeepai/multiomics-open-research/blob/main/checkpoints/bulk_rna_bert_gtex_encode/config.json). These are upstream source references, not a certification of an unavailable local installation.

- `prepare_tpm` preserves version-stripped unique input IDs, supplied vocabulary order, the 19,062-gene width, existing minimum coverage of 18,000, and historical zero-filling of absent vocabulary genes. It preserves requested sample order and produces contiguous float32 values. No new missing-gene imputation or stricter coverage method was introduced.
- The foundation route forms float32 log10(TPM+1) once, optionally applies the approved transductive correction, and sends `input_scale=log10_tpm` to the worker. The legacy worker receives TPM and applies the official log preprocessing once. The official tokenizer then performs its own fixed-factor normalization and binning. A copy protects the supplied array from the tokenizer's in-place normalization.
- Corrected inputs restore only vocabulary genes proven all-zero on retained samples before correction. Missing nonzero genes still fail. The existing recorded floor of negative corrected logged values to zero remains unchanged; no upper clipping, shift or second log is added.
- Expression-bin IDs must satisfy `0 <= id < n_expressions_bins`. A value at/above the tokenizer's highest expression edge can produce an ID outside that range; the existing rejection is retained, without admitting special-token IDs or silently saturating values. Additional checks reject malformed shapes, fractional IDs and nonfinite values. Checkpoint dimensions and required normalization flags remain checked, with finite positive normalization-factor/bin validation added.
- Frozen layer 4, its 256-wide contextual tokens, the historical key 0, all-gene mean pooling and all-valid vocabulary-position mask remain intact. New gene-ID metadata is separate from the tensors and does not add a model input.

Vocabulary digests establish replay of the **supplied** biological order. The framework cannot infer that an arbitrary user-supplied vocabulary is the checkpoint's true biological vocabulary merely from matching length. Matched assets must be supplied; existing saved asset-content/source checks remain in force. No checkpoint or vocabulary was downloaded, edited or repaired.

BulkFormer normalization and pooling were also checked against the existing public implementation and regression tests. `aggregate_type='all'` remains the historical elementwise **max + mean + median sum**, with the existing interested-gene order and masking behavior. No concatenation, pooling change or new representation was introduced.

## Numerical behavior

New CellFM one-view runs use different random draws from historical global-stream extraction. Canonical input order can also change floating-point reduction order compared with the old one-view source order. This is the necessary reproducibility correction, not a new sampling algorithm or an accuracy claim. The selected membership for a new single-view run can therefore differ from a historical run; no further reselection, post-extraction alignment or dimension change is performed. For the same sample/view seed, vocabulary and per-sample counts, new selection is independent of cohort/sample traversal and batch size. Intended transductive correction still changes when its correction cohort changes; stable selection does not make correction inductive.

CellFM twenty-view extraction retains its existing canonical-order/sample-view driver. Corrected CellFM continues to select from original capped/rounded counts and preserves IDs, masks, unmask channels, padding and count-derived library features, substituting only the intended corrected continuous scalar values. Missing selected genes or nonfinite encoder activations continue to fail. BulkFormer pooling and valid BERT transforms/bins retain their original numerical definitions.

## Saved-model compatibility

- Model import/class paths, network state dictionaries, widths, token dimensions, fitted representation logic, feature schemas and class/probability ordering remain intact. New token-schema/view attributes and extraction metadata are additive. Foundation bundle format remains 2; token-cache format remains 1. Existing format-1/2 foundation loading and checksum checks are preserved.
- Historical CellFM one-view foundation bundles without the new sampling marker explicitly select the original global-NumPy driver and source order, including corrected-input normalization/replay. New bundles select sample/view seeding. Unknown markers fail. The core legacy embedding route reads saved `cellfm_metadata.json` and rejects missing/unknown single-view replay metadata rather than guessing. Historical valid metadata without a strategy field uses the original global-stream convention.
- Historical one-view extraction retains its original dependence on cohort/order and original inputs. The compatibility path does not promise the new sampling invariant for old bundles. No existing bundle is rewritten or migrated.
- Historical `TokenModel` instances lacking new attributes retain their prediction path, including legacy cache records without identities and original view-summation order. New heads require their saved schema/view count. Fixed-order identity changes fail; valid CellFM sampled membership changes remain permitted. Newly tagged caches are validated even when consumed by a historical head, while untagged historical caches cannot gain retroactive identity validation.
- Legacy `.npy` token records without gene files remain readable. New BERT `.npy` records reference a shared, cache-contained gene-ID file. Path containment checks cover both token and identity files. Tests compare predictions before/after joblib serialization and assert that saved models/training bundles are not modified during prediction.
- The legacy BERT cache key includes worker source contents, so updated worker code can produce a new cache key. Existing cache files are not rewritten or deleted. Matching old models remain loadable; underlying valid-input transformations are unchanged.

Invalid gene IDs, masks, layouts or required replay metadata can now cause explicit failures where old code accepted unchecked input. Arbitrary dependency-version compatibility and numerical replay of historical models with unavailable original input/assets are not asserted. No manuscript model/result was read or migrated for these checks.

## Remaining limitations and stopping point

1. CellFM token positions retain the approved sampled-position limitation. The architecture supplies no globally fixed gene-position interpretation, and real-data generalization remains unmeasured. No replacement architecture, pooling or CLS support was introduced.
2. Real CellFM/BulkFormer/BERT checkpoints, local vendor execution and real GPU kernels were not run. CellFM collator/encoder tests use stubs and public protocol contracts; the upstream [CellFM preparation source](https://github.com/biomed-AI/CellFM/blob/main/data_process.py) was consulted for selection/mask conventions, but does not certify a particular supplied PyTorch port. Strict validation may expose an incompatible vendor layout instead of silently accepting it.
3. Native-R/limma numerical execution was not available in this isolated validation; the optional native-sva test requires `OMICLASS_TEST_SVA_LIB`. Synthetic correction bridges check routing/scope and scalar/token preservation. Transductive cohort dependence remains intentional.
4. Historical artifacts lacking identities, provenance or preprocessing state retain the explicitly described verification/replay limits. Earlier nested-CV/calibration small-sample/runtime limits and standalone fixed-head evaluation protocols remain unchanged.

All changes and validation writes are confined to `/data01/home/ls/katzm/omiclass-public`. No manuscript repository, running worker, shared environment/dependency, checkpoint or saved result was modified. Stage 6 stops here for review; publication cleanup and final release preparation have not begun.
